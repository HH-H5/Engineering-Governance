# Engineering-Governance

AI支援・AI駆動のソフトウェア開発において、複数のプロジェクトで共通して適用する開発ガバナンスを管理するリポジトリです。

このリポジトリには、個別プロジェクトの仕様や実装詳細ではなく、プロジェクト横断で適用する上位ルールのみを置きます。

## Purpose

このリポジトリの目的は、AIと人間が共同で開発するときに、

- 何を正本（Canonical Source）として扱うか
- 文書間の優先順位をどう判断するか
- AIが変更してよい範囲はどこまでか
- 人間の承認が必要な変更は何か
- 文書と実装が矛盾した場合にどう扱うか

を明確にすることです。

「正本」という用語の意味は `tier1/DOCUMENT_GOVERNANCE.md` で定義します。

## Document Tiers

開発文書は、権威の強さに応じて4つのTierへ分類します。

```text
Tier 1: Constitution
Tier 2: Contract
Tier 3: Knowledge / Procedure
Tier 4: Derived View
```

数字が小さいTierほど、上位の権威を持ちます。

詳細は以下を参照してください。

- `tier1/DOCUMENT_GOVERNANCE.md`
- `tier1/AI_AGENT_POLICY.md`
- `tier1/CHANGE_CONTROL.md`

## Scope

このリポジトリで管理するのは、複数のプロジェクトへ共通して適用できる原則です。

個別プロジェクト固有の以下の情報は、原則としてこのリポジトリでは管理しません。

- 製品仕様
- アーキテクチャの具体的構成
- API仕様
- 外部サービス設定
- デプロイ構成
- 運用Runbook
- 認証情報
- 秘密情報
- 個人情報
- 未公開の事業情報

これらは各プロジェクト側で管理します。

## Public Repository Policy

このリポジトリは公開リポジトリとして運用します。

そのため、追加する情報は次の条件を満たす必要があります。

> インターネット上の誰に読まれても問題がないこと。

「秘密情報ではない」というだけでは、公開する理由として十分ではありません。

公開する必要性がない情報、公開可否を判断できない情報、個別プロジェクトに依存する情報は、このリポジトリには追加しません。

認証情報、秘密鍵、アクセストークン、パスワード、個人情報その他の秘密情報は、いかなる場合もGit管理対象へ追加してはいけません。
